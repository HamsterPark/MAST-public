# 数据处理 agent 的分析运行时 —— 与 MAST 主进程**完全分开**的一套 CPython 3.13。
#
# 这不是 MAST 自己的依赖。它装进 <install_root>/MASTv2/pyruntime/，只被
# mast.pyexec 起的分析子进程使用。主进程一个都不 import。
#
# 为什么要单独一套（而不是复用冻结包里的 numpy/scipy）
# ====================================================
# PyInstaller onedir 把纯 Python 源编译进 MAST.exe 内嵌的 PYZ，_internal/ 下只剩
# .pyd —— `_internal/numpy/__init__.py` **不存在**，子进程 import 不了。
# ⚠️ 而 `_internal/nanonis_spm/__init__.py` **是真实文件**：把 _internal 放进子进程
# 的 sys.path 会让 B1（子进程里没有 nanonis_spm）当场失效。所以独立运行时不是
# 「更干净」的选择，是**唯一**的选择。
#
# 版本为什么钉死
# ==============
# `tests/v2/unit/pyexec/test_parser_parity_child_vs_parent.py` 断言同一个 .sxm 在
# 子进程和主进程解析结果逐元素相等。两边 numpy 版本漂开，那条测试就在量一个
# 不确定的东西。这里的版本 == `.venv-v2-py313` 里的版本（2026-08-20 实测对齐）。
#
# 改这个文件 = 要重发全量安装包
# =============================
# 运行时在 `MASTv2/` 子树下，而 `update/delta.py` 的 DEFAULT_EXCLUDE_TOP 排除整个
# MASTv2（只有三个 carve-back，都不是 pyruntime）。OTA delta **结构上碰不到它**。
# 这是接受的代价：钉死的解释器 + 钉死的 wheel 本来就该冻结。
#
# ⚠️ dep_pin 钩子（不随仓） 会匹配到这个文件名，但它只 pin
# langgraph/langchain/torch/transformers/pydantic/anthropic —— 都不在这里。
