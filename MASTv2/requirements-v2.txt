# --- Word 导出（报告/论文草稿 → .docx，给人用修订/批注改） ---
# HTML 自包含导出覆盖「发给别人看」，但覆盖不了「让别人改」：导师/合作者要走 Word
# 的修订与批注，期刊也不收 HTML 投稿。渲染器在 mast/agents/_shared/report_docx.py，
# **全部挂 Word 内置样式**（Heading 1 / Normal / Caption / Table Grid …），从不硬编码
# 字号颜色 —— 收件人改一次样式就能重排全文，套期刊模板只是一次样式替换。
#
# 选它而不选 pandoc / Word COM 自动化的理由：
#   pandoc  —— 转换质量最好，但是个 ~150 MB 外部二进制，得装、得随安装包发、还得
#              在打包版里找得到，会破坏「一个 exe 自包含」。
#   Word COM —— 保真度最高，但要求目标机装 Office（rig 不一定有），而且会拉起
#              一个 WINWORD.EXE；一个自治系统里不该有能挂住、又不好超时杀掉的外部
#              进程（同 Nanonis 端口那类教训）。
# python-docx 是纯 Python、离线可用、PyInstaller 能打包。
#
# 打包注意：它自带 ~440 KB 的模板数据（docx/templates/，其中 default-styles.xml
# 就是 Heading 1 / Caption 这些**内置样式的定义**），mast2.spec 必须
# collect_all("docx")，否则打包版 Document() 直接失败 —— 而那是「打包成功、功能
# 在仪器上不存在」那类静默失效。实测 collect_all 收到 datas=120 / hidden=95，
# 其中 23 条是模板数据。
python-docx>=1.2,<2
